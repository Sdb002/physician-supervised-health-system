# Food Dataset Schema — `bd_food.csv`

One row per food item. **All nutrient values are per 100 g edible portion, as consumed** (i.e., cooked values for foods normally eaten cooked).

> **Current contents: 250 foods from the Food Composition Table for Bangladesh**
> (INFS, University of Dhaka & FAO, 2013), generated by
> `scripts/convert_fct_food.py` from the raw export in `data/food/raw/`.
> Known limitations: the source table has no folate column (`folate_ug` is 0
> for every row); values are raw unless the item name says boiled/fried/dried;
> `name_bn` is Roman transliteration until the sheet is re-exported as UTF-8;
> trace/not-reported values are stored as 0. Do not hand-edit `bd_food.csv` —
> fix the raw export or the converter and re-run it, then
> `py scripts/validate_datasets.py`.
>
> **Corrected transcription errors (2026-07-31):** `F198` Chicken breast and
> `F081` Spinach, raw had iron/calcium values in `data/food/raw/` that were
> physiologically implausible (e.g. 32 mg iron/100g for chicken breast — more
> than beef liver) and, cross-checked against USDA FoodData Central, were off
> by 1–2 orders of magnitude. Corrected in the raw export: chicken breast
> iron 32.0→0.4 mg, calcium 1→5 mg; spinach iron 52.0→2.7 mg, calcium 2→99 mg
> (USDA FDC raw spinach: ~2.7 mg iron, ~99 mg calcium per 100 g). An automated
> per-food-group outlier scan (z-score on iron/calcium) flagged a few other
> rows (e.g. dried dates iron) as worth a closer look in a future data audit,
> but only these two — the ones actually driving a reported patient plan's
> nutrient-coverage numbers past 900% — were corrected here.

## Columns

| Column | Type | Unit | Description |
|---|---|---|---|
| `food_id` | string | — | Unique ID, pattern `F###`. Referenced by `recipe_ingredients.csv`. |
| `name_en` | string | — | English name. |
| `name_bn` | string | — | Bangla name (UTF-8). |
| `food_group` | string | — | One of: `grain`, `legume`, `vegetable`, `fruit`, `fish`, `meat`, `egg`, `dairy`, `oil`, `sweet`, `spice`, `other`. |
| `kcal` | float | kcal | Energy. |
| `protein_g` | float | g | Protein. |
| `carb_g` | float | g | Total carbohydrate. |
| `fat_g` | float | g | Total fat. |
| `fiber_g` | float | g | Dietary fiber. |
| `iron_mg` | float | mg | Iron. |
| `calcium_mg` | float | mg | Calcium. |
| `zinc_mg` | float | mg | Zinc. |
| `folate_ug` | float | µg | Folate (DFE). |
| `vit_a_ug` | float | µg RAE | Vitamin A. |
| `vit_c_mg` | float | mg | Vitamin C. |
| `sodium_mg` | float | mg | Sodium. |
| `potassium_mg` | float | mg | Potassium. |
| `tags` | string | — | `\|`-separated flags used by the matcher and the contraindication gate, e.g. `iron_rich\|high_sodium`. Vocabulary listed below. |
| `source` | string | — | Citation for this row's values. `DEMO` marks placeholder data. |

## Tag vocabulary

`staple`, `high_protein`, `lean`, `high_fiber`, `iron_rich`, `calcium_rich`,
`potassium_rich`, `leafy_green`, `fruit`, `dairy`, `probiotic`, `omega3`,
`oil`, `high_fat`, `high_sugar`, `high_sodium`, `dessert`.

Tags prefixed nowhere and matched exactly. `high_sodium`, `high_sugar`, `high_fat`
are **exclusion tags** referenced by `data/reference/contraindications.yaml` — the
contraindication gate removes foods carrying an excluded tag for the patient's
conditions. Add new tags freely, but register exclusion tags in that YAML.

## Validation rules (enforced by `scripts/validate_datasets.py`)

- `food_id` unique, matches `F\d+`.
- All nutrient columns numeric and ≥ 0; `kcal` ≤ 900.
- `food_group` from the list above.
- Every tag from the vocabulary above (warns on unknown tags).
