# Recipe Dataset Schema

Three files, generated by `scripts/convert_datasets.py` from the Bangladeshi
Recipe Dataset 250 (v2, 2026-09-27) in `data/recipe/raw/`: 250 home-cooked
Bangladeshi dishes, 2,349 ingredient rows using 172 foods, 1,105 method
steps. The master workbook `raw/Bangladeshi_Recipe_Dataset_250.xlsx` also
holds the method, 37 source citations, the USDA retention / FCTB yield factor
tables and the FCTB cooked-dish benchmark; the three raw CSVs are verbatim
exports of its Recipes / Ingredients / Steps sheets.

**Recipes carry no nutrient columns** — per-serving nutrition is always
computed at runtime by `src/diet/recipe.py` from the ingredient list joined
against `data/food/bd_food.csv`, so a corrected food flows into every recipe
that uses it. The calculation is the dataset's own FAO/INFOODS mixed-recipe
method (raw ingredient grams × per-100 g values, vitamins A and C × the
ingredient's USDA retention factor, ÷ servings); for every recipe that uses no
corrected food it reproduces the workbook's per-serving values exactly.

Validate with `py scripts/validate_datasets.py` (it cross-checks that every
`food_id` exists in `bd_food.csv`).

## Household frequency score

`weekly_frequency_score` is the dataset author's expert ordinal score of how
commonly a dish is cooked in a typical Bangladeshi household — **10 = the most
commonly cooked dish, 1 = rare/special**:

| Score | Tier | ≈ servings/week | Recipes |
|---|---|---|---|
| 10 | Daily staple | 14 | 1 |
| 9 | Near-daily | 7 | 2 |
| 8 | Very frequent | 5 | 3 |
| 7 | Very frequent | 4 | 1 |
| 6 | Frequent | 2.5 | 13 |
| 5 | Weekly | 1.5 | 31 |
| 4 | Regular | 0.7 | 67 |
| 3 | Occasional | 0.3 | 78 |
| 2 | Festive/seasonal | 0.1 | 51 |
| 1 | Rare/special | 0.03 | 3 |

The recipe ranking uses it as a familiarity weight: a dish's nutritional fit
is multiplied by 0.25 + 0.75 × (score − 1) / 9 (1.0 for a score-10 staple,
0.33 for a score-2 festive dish), so among dishes that suit the patient, the
ones households actually cook rank first — a festive dish needs about three
times the nutritional fit of a daily staple to outrank it (see
`src/diet/matcher.py`, `frequency_multiplier`).

## `recipes.csv` — metadata

| Column | Type | Description |
|---|---|---|
| `recipe_id` | string | Unique ID, `BDR-` + 3 digits (the source id). |
| `name_en` | string | English name. |
| `name_bn` | string | Bangla name (script). |
| `name_bn_roman` | string | Romanised Bangla name. |
| `category` | string | Dish family: Vegetable, Fish, Meat, Bhorta, Rice & Grain, Bread & Pitha, Leafy Green, Sweet, Dal, Snack, Egg, Beverage, Salad & Chutney. |
| `meal_type` | string | `\|`-separated: `breakfast`, `lunch`, `dinner`, `snack`. The source's iftar / dessert / beverage slots map to `snack`; festival is an occasion, kept as a tag. |
| `diet_type` | string | Vegan, Vegetarian, Ovo-vegetarian, Pescatarian or Non-vegetarian. |
| `weekly_frequency_score` | int | 1–10, see above. |
| `frequency_tier` | string | The score's label (must match the table above). |
| `servings` | int | Servings the ingredient list yields (> 0). |
| `serving_size_g` | float | Estimated cooked grams per serving (FCTB yield factors). |
| `cooking_method` | string | Readable method (Boiled, Bhuna, Curry, …). |
| `total_time_min` | int | Preparation + cooking time. |
| `tags` | string | `\|`-separated descriptive tags: diet (`vegan`, `pescatarian`, …), occasion (`festival`, `iftar`, `dessert`, `beverage`), `deep_fried`, and allergen/restriction flags (`contains_dairy`, `contains_egg`, `contains_fish`, `contains_shellfish`, `contains_nuts_seeds_coconut`, `contains_mustard_seed`, `contains_gluten_wheat`, `contains_beef`). Exclusion tags (`high_sodium`, `high_sugar`, `high_fat`) are **derived at runtime** from the ingredients — do not add them here. |
| `notes` | string | Dish notes, including clinical notes (e.g. star fruit and kidney disease). |
| `source` | string | Dataset, provenance tier and source ids (Sources sheet of the workbook). |

## `recipe_ingredients.csv` — join table

| Column | Type | Description |
|---|---|---|
| `recipe_id` | string | References `recipes.csv`. |
| `seq` | int | Order in the recipe. |
| `food_id` | string | References `data/food/bd_food.csv`. |
| `qty_g` | float | Raw edible grams for the whole recipe (all servings) — same state as the food row (raw unless the food row is a cooked item). |
| `household_measure` | string | How a cook measures it ("1 medium onion, sliced"). |
| `role` | string | staple, main, vegetable, spice, oil, garnish, … |
| `is_optional` | 0/1 | Optional ingredient (still counted in nutrition, as in the source). |
| `rf_vit_a`, `rf_vit_c` | float | USDA Release 6 retention factors (0–1] for this ingredient's food group × cooking method. |

## `recipe_steps.csv` — method

| Column | Type | Description |
|---|---|---|
| `recipe_id` | string | References `recipes.csv`. |
| `step_no` | int | 1, 2, 3, … per recipe. |
| `instruction` | string | One cooking step (English). |

## Runtime-derived exclusion tags (`src/diet/recipe.py`)

- An ingredient's `high_sodium` / `high_sugar` / `high_fat` tag is inherited
  when that ingredient is ≥ 25% of the recipe's weight.
- `high_sodium` when one serving has > 600 mg sodium.
- `high_sugar` when `added_sugar` ingredients supply > 10% of the energy (WHO
  2015) — matches the dataset's own added-sugar flag on all 39 recipes.
- The tags read off a food's name and group (`src/diet/restriction_tags.py`:
  `contains_meat`, `liver`, `solid_fat`, …) are inherited from every
  ingredient, in any amount: a dish finished with a spoon of ghee carries
  `solid_fat`, which the high-cholesterol rule excludes (25 dishes).

## Validation rules

- `recipe_id` unique and `BDR-\d{3}`; every ingredient and step row's
  `recipe_id` exists in `recipes.csv`.
- Every `food_id` exists in `bd_food.csv`.
- `servings` integer > 0; `serving_size_g` > 0; `qty_g` > 0; retention
  factors in (0, 1].
- `weekly_frequency_score` an integer 1–10; `frequency_tier` matches it.
- At least one valid `meal_type`; `source` present.
- Every recipe has at least one ingredient row; step numbers run 1..n
  (warning if a recipe has no steps).
